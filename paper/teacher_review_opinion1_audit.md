# 第二份老师初稿审稿意见逐条审计

## 审计结论

本报告将老师提供的《论文审稿意见1.md》与当前版本 `paper/main.pdf` 对照，判断每条意见的技术有效性、修改价值和是否构成初稿提交的阻断条件。审计不读取代码，也不对老师引用的外部论文做联网核验；因此凡是涉及 [17]、[18]、[33]、[34] 原文目标函数的地方，只能判断“是否需要核实”，不能直接判定老师的外部文献判断为事实。

总体结论：这份意见的技术含量高于上一份，提出的数据泄漏边界、max-over-search 选择偏差、基线覆盖、TPS 对照、IGPSO/MEL 复现和可复现性问题，大多具有真实参考价值。但它把 benchmark 算法比较协议与外部泛化评估混为一谈，把后续增强实验全部列为 P0，并且把若干当前 PDF 已经修正或明确承认的问题再次列为“硬伤”。因此，“59/100、必须完成 P0 后才能送外审”的结论偏重。

针对“交初稿、没有原则性大问题即可”的目标，当前 PDF 的合理判断是：**可以提交初稿；建议在提交前完成若干说明性小修和有限实验补充，但不需要立即重做整套嵌套交叉验证或全部新增基线。**

## 分类标准

| 分类 | 解释 | 对当前初稿的处理 |
|---|---|---|
| A：确实有用，建议优先改 | 当前 PDF 有真实歧义、表述风险或复现缺口 | 送出前尽量处理 |
| B：有价值但非硬门槛 | 能增强说服力，但不影响核心研究成立 | 后续版本或补充材料处理 |

## 一、领域专项核查表 A–G

### A. 创新性：三模块已有渊源、机制级区分不够

**分类：A/B。**

老师指出 MI 先验、精英局部搜索和动态权重分别存在已有渊源，这个提醒是合理的。当前 PDF 的创新主要是闭环组合和在 MEL 双群骨架上的协同设计，而不是声称每个基础机制都首次提出。Section 2.4 和 Table 1 已经做了初步定位，但与 [17]、[18]、[33]、[34] 的逐机制差异仍可进一步明确。

不过，老师把“没有逐机制对比”直接提升为创新性核心缺陷并不完全成立。论文已经给出竞品分类表和方法组件维度，且当前稿件的创新主张是系统集成与前后改进链条，而非单一算子原创。

**建议：** 增加一段机制级差异说明，优先比较初始化、在线记忆、记忆衰减、精英精修和动态权重。无需因为创新不是“全新理论”就大幅下调论文价值。

### B. 适应度与方法学：内部 CV、max-over-search、MI 先验泄漏

**分类：A，但老师的“Fail/结果不可信”判断过重。**

这一组意见是整份审稿中最有用的部分，但需要区分三个概念。

第一，当前 PDF 第 11–12 页确实把每个数据集作为一个自包含 benchmark instance，并使用内部 5-fold CV 作为 wrapper fitness。搜索过程中不断更新并最终报告 gbest，确实意味着报告的是“在该搜索协议下获得的最优内部 CV 结果”，不能直接解释为无偏外部泛化误差。老师称其为 max-over-search selection bias，在泛化评估意义上是成立的。

第二，这并不自动使 Table 4 的算法比较“绝对不可信”。进化特征选择 benchmark 的常见目的本来就是比较固定搜索协议下的相对组合优化能力。只要论文明确把结果称为 benchmark-level internal CV performance，并不把它宣传为独立测试性能，该协议仍然可以用于算法间相对比较。当前 PDF 第 11、17、18 页已经承认了这一边界。

第三，关于 MI 先验是否在全部样本上计算，当前 PDF 的写法存在歧义，但没有足够证据证明已经发生了泄漏。Section 3.2.1 一方面规定 inductive deployment 时先验在 training partition 内计算，另一方面说明 benchmark instance 使用完整数据集和内部 CV surrogate。老师指出需要把 benchmark 实现写清楚是正确的；但“已确认 MI 泄漏”是超出当前 PDF 证据的结论。

**建议：** 送出前明确写出：当前结果用于共享 benchmark 内部搜索比较；若采用 benchmark 全数据先验，则不得称其为无偏泛化；若实际实现是每个训练折重算，则应明确写出。嵌套 CV 可作为后续增强，不是初稿提交硬门槛。

### C. 实验设计：缺 filter、embedded 和 top-k 强基线

**分类：B，建议有选择地采纳。**

这条意见有实质价值，因为 KDS-EL 强调准确率、稀疏性和时间的综合权衡，而当前主要比较对象是进化/群智能 wrapper。增加一个 mRMR/MI top-k + 3-NN 参考点，尤其是按 KDS-EL 特征数对齐的 top-k 参考点，能够直接说明进化搜索相对于简单筛选的增量价值。

但 filter 和 embedded 方法不是本文唯一研究对象。当前论文主题是 evolutionary wrapper feature selection，Section 2 已经讨论 filter 和 embedded 的优缺点，不能因为没有把所有范式都实测就判定实验设计 Fail。L1、RF importance、ReliefF 等新增方法也会引入新的调参和实现公平性问题。

**建议：** 若能增加实验，优先加入一个 MI/mRMR top-k 对齐参考，而不是一次性加入四个新范式。若初稿时间有限，在 limitation 中说明比较范围即可。

### D. 统计检验：总体合格，CD 值需核验

**分类：A（核验项）+ B（扩展项）。**

老师对当前统计体系的总体评价“Pass”是合理的。当前 PDF 已区分逐数据集 Mann–Whitney U 与跨数据集 Wilcoxon signed-rank，并使用 Friedman、Holm–Bonferroni 和 rank-biserial effect size。与上一份意见不同，当前版本没有明显的统计检验名称混用。

Fig. 6 的 `CD = 3.25` 值值得核对公式、临界值和是否采用了 Nemenyi/其他 post-hoc 设定。仅凭老师给出的约 3.7 不能直接证明图中数值错误，因为临界值表和计算约定可能不同。建议补充计算式或删除 CD 数字，避免无来源的精确值。

特征数差异的统计检验属于有价值的多目标扩展，但不是当前准确率统计体系失效的证据。

### E. 复杂度与效率：评价基本正确

**分类：D/A。**

老师对 Section 3.5.1 和 Section 4.2.6 的评价基本准确。当前 PDF 已报告 51.3 s、175.0 s、326.2 s，并将加速主要归因于 active feature compression 和 k-NN 距离计算随选中特征数线性增长，同时承认 KDS-EL 每代有 elite refinement 额外评估。因此，这一部分不需要按“效率论证缺失”重写。

可补充的是硬件、线程和实际候选调用次数，以提高可复现性。

### F. 结果呈现：缺 bIRIME/BinCOA 收敛曲线、代码未公开

**分类：B/C。**

Fig. 5 的图注明确写的是 representative wrapper methods，并非声称展示所有方法。因此缺少 bIRIME/BinCOA 不是图表错误，只是如果想论证“最强竞争者的收敛过程”会更完整。代码未公开是复现增强项，当前 `Data will be made available on request` 不理想但不构成初稿原则性问题。

### G. 写作：“N_samp << 100”与千级样本数据集

**分类：A，建议修改。**

这是老师意见中很准确的一条。Table 2 同时包含数千样本的数据集，而引言和方法中多次将 `N_samp << 100` 写成整个实验范围的统一条件。即使算法确实面向高维小样本，当前表述也容易被读者理解为所有数据集都属于极端样本稀缺。

**建议：** 将动机改为“部分基因表达数据处于 severe sample-scarce regime，而文本、图像和语音数据覆盖 moderate-sample high-dimensional regimes”，并在结果中按数据类型或样本规模解释 ISOLET/BASEHOCK 的差异。

## 二、六项 Major Issues 逐条判断

### M1. 内部 CV 选择偏差与 MI 内层泄漏

**最终分类：A/C。**

需要修改的是协议边界和实现说明，不是立即重做全部实验。老师要求至少 10 个数据集补 nested CV、双列报告内部/外部精度，这对正式终稿有价值，但对当前 benchmark 初稿属于高成本增强项。当前 PDF 已经明确不把内部 CV 等同于临床外部验证，并在第 18 页提出 nested CV 作为未来工作方向。

需要特别避免的是把 Colon 从 79.23% 到 94.52% 的差异直接当作“已证明搜索过拟合”。这个差异可以提示 3-NN 代理偏好或选择偏差，但也可能来自真实子集发现、全特征距离受维数灾难影响等多种机制。老师提出的是可检验假说，不是仅凭该数字即可下的结论。

**当前最小修订：** 明确 internal benchmark accuracy、MI 计算折次、预处理折次和外部泛化限制。nested CV 放入后续增强计划。

### M2. 缺 filter/embedded 和 top-k 基线

**最终分类：B。**

这是有价值的对照增强，但不是“必须解决否则不能送审”的硬伤。若增加一个 MI/mRMR top-k 对齐参考，收益最大；一次性加入四个 filter/embedded 方法并非必要。

### M3. 缺 [17][18][33][34] 最新直接工作

**最终分类：B/C。**

当前 PDF 已引用这些工作，并说明其中部分方法采用 Pareto archive、属于不同范式。老师要求逐条核实是合理的，但“[18] 很可能是标量化，因此属于选择性排除”只是推测，不能作为已确认问题。

**建议：** 不联网核验时不要直接承认排除理由错误。可在正文中增加“这些方法采用的目标形式与本文 scalarized wrapper protocol 不同，故未纳入主表”的证据性说明；若核实后发现是同类标量化 wrapper，再考虑补实验。

### M4. 单分类器 wrapper

**最终分类：A（结论限定）+ B（扩展实验）。**

老师指出 3-NN 可能使搜索偏向局部度量几何，这个方法学提醒成立。当前 PDF 已在 Section 4.2.8 承认 Colon 上 SVM/RF 的下降，因此论文没有完全回避该问题。

但要求把 SVM/RF 跨模型验证扩展到全部 20 个数据集并重新排名，属于较大扩展，不是初稿硬门槛。当前应把结论限定为“3-NN wrapper 下的搜索性能”，并把 S9 的跨模型结果定位为有限的 transferability check。

### M5. TPS 只对比一个静态权重

**最终分类：A/B，属于最值得补的小型实验之一。**

当前 Table 3 和 Table 8 只用 `[0.90,0.10]` 作为无 TPS 配置。这样可以说明 KDS-EL 比一个静态配置好，但不能完全分离“动态调度的价值”和“后期使用高 accuracy 权重的价值”。老师提出比较 `[0.95,0.05]` 静态权重或线性渐变是有逻辑的。

不过这不是原则性错误。TPS 是一个工程性调度机制，单点静态对照仍然能支持初步贡献分析。若有时间，建议至少补一个 `[0.95,0.05]` 静态对照，不必立即完成完整五点网格和线性调度。

### M6. 竞品复现有效性

**最终分类：A/B。**

IGPSO 的确被当前 PDF 明确写成 adapted ANOVA-guided implementation，而不是原始 MLP pipeline；这是一项透明披露，但也意味着不能把结果表述成对原始 IGPSO 的严格复现。MEL 的权重设置、DENCA-SO 的 surrogate 评估方式也值得在表注中说明。

老师要求为三个竞品制作原文复现验证表、为 IGPSO-MLP 做失败实验，属于高价值但高成本的增强。初稿阶段最重要的是：明确标注“adapted implementation”、避免把它写成 exact replication、说明 MEL 参数依据，以及把 DENCA-SO 与 full wrapper 的效率比较解释为不同评估范式下的工程比较。

### M7. 可复现性

**最终分类：B，正确方向但不是初稿硬门槛。**

公开代码、配置、种子、折索引和预处理脚本当然能显著增强可信度，尤其本文算法包含 Eq. (21) 自适应噪声、TPS 边界重校准和精英替换等实现细节。但当前 PDF 已给出主要参数、10 次运行、固定 CV seed、完整算法伪代码和补充表；`Data will be made available on request` 对初稿而言不足但并非原则性科学错误。

## 四、评分是否合理

老师给出的分项评分为：创新性 3/5、技术严谨性 3/5、实验充分性 3.5/5、写作 4/5，总体 3/5。若作为“严格高水平期刊终稿预审”，这个分项结构可以理解；但若评价的是“初稿是否存在原则性问题”，技术严谨性和总体结论偏低。

更符合当前 PDF 的初稿评分大致为：创新性 3.5–4/5，技术严谨性 3.5–4/5，实验充分性 3.5–4/5，写作质量 4/5，总体约 3.7–4/5，折算百分制约 **82–85/100**。

下调分数的真正依据应是：benchmark 内部 CV 与外部泛化边界仍需更清晰、MI 计算折次存在歧义、TPS 静态对照较单一、竞品中 IGPSO 是适配变体、代码尚未公开。不能把“未做 nested CV、未补四类基线、未对所有效率指标做统计”全部作为当前论文已经失败的证据。

## 五、修改路线的重新分级

### 建议作为送初稿前的 P0 小修

1. 明确 benchmark-level internal CV 与 external generalization 的边界。
2. 明确 MI、标准化、缺失值处理和其他预处理的实际执行折次；不能保留含混表述。
3. 将 `N_samp << 100` 限定为适用的数据子集，不要覆盖所有 Table 2 数据集。
4. 在 Table 3 补充 σ，统一 bIRIME、MEL 等算法名称和参数来源。
5. 明确 KDS-EL 的比较协议是同步 `N`、`T`，而不是严格相同的候选评估次数。
6. 对摘要、Highlights 和结论中的 95.45%、87.8、3.4× 加上内部 CV、benchmark 和当前实现环境限定。
7. 核对 Fig. 6 CD 值；若无法在正文给出计算依据，则删除该精确数字。

### 建议作为有条件的 P1 增强

1. 增加一个 MI/mRMR top-k 对齐参考，直接测试进化搜索的增量价值。
2. 增加 `[0.95,0.05]` 静态 TPS 对照，或至少在 limitation 中承认当前只对比一个静态点。
3. 在正文增加 ISOLET/BASEHOCK 失败模式和 3-NN 归纳偏置限制。
4. 明确 IGPSO 是 adapted ANOVA variant，并在补充材料说明与原始 MLP 版本的关系。
5. 补充运行环境、候选评估次数、TPS 边界重评估是否计入 runtime。
6. 说明 `multi-task` 在本文中沿用 MEL 的连续-离散双群协同含义。

### 适合后续终稿或返修阶段的 P2

1. Nested CV 或独立测试集。
2. 全部 20 个数据集的 SVM/RF transferability。
3. Filter、embedded、多目标 wrapper 的完整比较套件。
4. 特征数、稳定性、冗余度和运行时间的完整非参数统计。
5. 竞品原文复现验证、IGPSO-MLP 失败实验和公开代码/Zenodo 仓库。
6. KER 自适应 `k_flip` 上限、接受率和多样性指标。

## 最终判断

这份老师意见中真正应优先采纳的，是：评估协议边界与 MI 计算折次、`N_samp << 100` 的范围限定、TPS 对照不足、IGPSO 适配实现的透明标注、MEL 参数核对、σ 缺失、运行环境与预算说明，以及结论措辞收敛。

可以暂不采纳或降级处理的，是：必须立刻做 nested CV、必须补四类 filter/embedded 基线、必须扩展全部 20 个数据集的 SVM/RF、必须对所有非准确率指标重做 Friedman/Wilcoxon、必须提供 IGPSO-MLP 失败证据、必须公开代码后才能送初稿。这些都能提高正式投稿竞争力，但不是从当前 PDF 推导出的初稿阻断条件。

与当前 PDF 明显不符或不能由 PDF 直接证明的，是把 Fig. 5 缺 bIRIME/BinCOA 视为错误、把 Eq. (23) 或 Eq. (4) 作为当前版本错误、直接断言 MI 已经发生全集泄漏、以及直接断言 Colon 的性能提升已经证明搜索过拟合。

**基于当前 PDF，建议结论为：初稿可以提交；先做 P0 小修即可。内部质量评分约 82–85/100，比老师给出的 59/100 更符合当前版本实际状态。**
