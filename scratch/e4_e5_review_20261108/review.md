# E4 / E5 当前代码复查（2026-11-08）

## 审查结论与边界

当前代码仍存在影响运行完成和结果可信度的问题，尚不建议直接启动正式全量实验。确认的问题包括 E4 汇总故障链、DENCA 必然耗尽最终评分预算、bIRIME 适配偏离仓库原实现、完整性门禁遗漏、KER 接受率统计偏差、LDA 模型口径变化及报告预设结论。

本次只新增审查和复现材料，没有修改 `code/` 下的实现，没有改写正式 `output/` 结果。源文件 SHA-256 记录在同目录 `source_hashes.json`，复现结束后逐一验证未变更。全部数值例子均为明确标记的合成测试，不是论文性能数据。

审查范围为 `code/run_experiment_e4.py`、`code/run_experiment_e5.py` 及直接依赖的 `code/algorithms_nested.py`、`code/nested_evaluator.py`，并对照仓库 `code/algorithms/birime.py`。本次报告针对当前版本，不能把上一轮已修复的问题继续当作现存缺陷。

## [P1] E4 新增 OOF 汇总存在三个连续阻断点

位置：`code/run_experiment_e4.py:487–519`、`650–661`。

`execute_e4_single_run()` 返回的 `run_record` 没有 `test_indices`，但汇总直接读取 `rec["test_indices"]`。在一个真实的、使用合成数据执行的小规模单次优化及五模型外层评估后，复用其原样返回记录执行 orchestrator，抛出 `KeyError: 'test_indices'`。这些测试没有替换单次运行的优化器、评分器或外层分类器。

补充索引仍不足以修复链路。第 656 行引用不存在的 `outer_folds`，函数参数实际名为 `folds`；该错误会在覆盖全部样本、布尔表达式右侧实际求值时暴露。第 659–661 行还使用从未导入的 `accuracy_score`、`balanced_accuracy_score`、`f1_score`。定向补充前置字段和名称后，分别复现了 `NameError: name 'outer_folds' is not defined` 与 `NameError: name 'accuracy_score' is not defined`。

影响是非空成功运行结果进入汇总后报错，无法正常产出最终汇总 JSON 和报告；此前的 detailed JSON 已写出，因此已有计算结果并非必然全部丢失。应完整补齐结果契约、正确使用折数参数并导入评分函数，同时增加单折诊断及完整五折的端到端测试，不能只修第一个异常。

## [P1] E5 扩展 DENCA 在最终评分前必然耗尽预算

位置：`code/algorithms_nested.py:1387–1392`、`1401–1428`；预算拒绝逻辑为 `code/nested_evaluator.py:197–198`。

初始化和 DE 循环直接递增 `candidate_eval_requests`，循环持续到 `has_budget()` 为假。随后又调用同一个 `evaluator.evaluate(final_mask)`，其预算检查立即拒绝。增加预算并不能修复，因为循环会把新增预算也全部用完。

复现仅替换昂贵的 NCFS 权重估计，保留真实 BudgetEvaluator。预算为 20、41、2000 的三种情况全部抛出 `BudgetExhaustedException`；默认 2000 情况中 candidate=2000、shortcut=2000、CV=0、unique masks=0。这也说明把 filter 目标请求直接塞进 infeasible-shortcut 计数器并不忠实表达评分语义。

影响范围是 E5 的 `--mode all` 或显式选择 `DENCA_SO`；默认 core 不包含它。应先明确 filter 目标与最终 wrapper 评分的预算契约，至少为最终评分预留请求，并独立记录 filter 请求，禁止通过直接篡改计数器伪装为不满足特征数的快捷返回。

## [P1] E5 bIRIME 仍与仓库原算法在搜索机制上不一致

位置：`code/algorithms_nested.py:535–556`，对照 `code/algorithms/birime.py:79–105`。

CMS 已恢复，不能继续称其缺失。但 Soft-Besiege 在原实现中具有 `r < 0.5` 与 `r >= 0.5` 两条路径；适配版本只保留一条，并把原本独立抽取的幅度随机数替换为分支随机数 r。原实现的群体均值路径完全未执行，这不是仅更换评分器或停止准则。

RimeFactor 也由依赖 T 的连续日程改为 `t % 10` 和 `t % 50`，改变了符号和衰减轨迹。例如 T=100、t=10，原余弦因子为 -1，适配版为 +1。即使固定公平请求预算，也应显式定义并记录日程映射，而不能悄悄改变机制。

在相同种子 7、相同 N=20、同一确定性评分函数下捕获两个实现前 100 个候选请求：初始化前 20 个掩码完全一致，第 21 次请求即发生差异。该测试证明了局部适配不一致，不是对外部官方实现的独立正确性认证，也不意味着不同停止准则下的整个算法本应永远逐位一致。应恢复原分支，并对适配日程建立可验证的明确协议。

## [P1] 完整性标志未覆盖五折 OOF 有效性和审计状态

位置：`code/run_experiment_e5.py:458–465`、`474–508`；E4 对应 `code/run_experiment_e4.py:687–721`。

E5 的组装器已能返回 `is_complete_5fold` 和 `coverage_ratio`，但 orchestrator 随即丢弃这些状态。顶层 `is_complete` 只看任务是否返回及是否抛运行异常，不检查审计是否通过，也不检查组装是否成功。组装异常仅打印 warning，不加入失败清单。

使用真实 orchestrator、真实 OOF 组装器及报告生成器，注入明确的合成运行记录后，确认三个独立案例：只运行一折、覆盖率仅 0.2 时，顶层仍为 complete=true；五折全部 audit=false，仍为 complete=true；五折预测长度损坏导致 OOF 组装失败、汇总 results 为空时，仍为 complete=true。三者均未出现 incomplete banner。底层单折指标本来正确返回 complete_5fold=false，问题出在上层状态被丢弃。

E4 在绕过上文三个阻断点后，同样可以出现 complete_5fold_seeds=0 而顶层 complete=true，其默认参数恰好只运行第一折。审计失败的记录也未被排除在正式均值之外。

建议区分任务完成、有效预测、审计通过、完整五折和正式汇总就绪等状态。正式汇总必须要求预期的五个互异外折、每个样本恰好一次 OOF 预测、全部审计通过及组装成功；单折诊断可以保留，但应明确与正式五折结果隔离。

## [P2] E4 KER 接受率剔除了零成功种子

位置：`code/run_experiment_e4.py:692`、`710`。

代码仅将 `ker_accept_rate > 0` 的种子纳入均值。只要至少一个种子成功，所有有尝试但完全未接受的种子都会被排除，产生向上偏差。

在绕过 E4 汇总阻断点的隔离测试中，两种子各执行五折、每折均有 10 次尝试，一个种子接受率为 0，另一个为 1。正确的等权均值和总接受数/总尝试数均为 0.5，实际报告为 1.0。建议保留全部有尝试的种子，或者明确使用总接受数除以总尝试数，并在折与种子层面统一口径。零尝试与零成功不能混同。

## [P2] LDA 根据特征数切换模型，异常后又回到高内存路径

位置：`code/nested_evaluator.py:378–434`，报告模型名称为 `code/run_experiment_e5.py:557`。

不超过 1000 个特征时使用 `lsqr + shrinkage='auto'`，超过 1000 个特征时直接改为不带 shrinkage 的 SVD LDA，但最终表仍统一称作 Shrinkage LDA。这使紧凑与宽特征子集接受不同的正则化学习器评估，结果不再能仅解释为固定分类器对特征子集的比较。

此外，宽子集的 SVD 失败后，无条件的第一层回退仍使用 `lsqr + shrinkage=0.1`，重新进入需要高维协方差矩阵的路径，与前面的内存保护目标相冲突。

用可记录构造参数的轻量 LDA 替身观察到：1000 维为 lsqr/auto，1001 维为 svd；对 1001 维注入首次 SVD 失败后，下一个构造器确实为 lsqr/0.1。此处没有故意分配真实超大协方差矩阵或制造真实 OOM。建议固定一致且可承受的分类器协议；若必须异构回退，至少在最终统计中区分模型及回退率，宽特征情况下禁止回到协方差密集型回退。

## [P2] E5 报告在没有任何结果时仍输出肯定性结论

位置：`code/run_experiment_e5.py:634–637`。

三段学术结论完全是固定字符串，不依赖 agg_table、审计状态、算法比较结果或显著性检验。传入空汇总、completed=0、planned=5、is_complete=false 时，虽然顶部有不完整警示，末尾仍断言优势持续、多指标取舍更优和跨模型迁移稳健。

这会把实验执行结构直接当作实证结论。应在有效完整数据不足时仅输出诊断说明；结论必须由可核验的实际比较计算触发，并在混合结果时保留失败与取舍。加一个 warning banner 不能抵消正文中相反的无条件声明。
